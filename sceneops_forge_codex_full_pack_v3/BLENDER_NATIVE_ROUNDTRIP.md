# Blender 原生资产编辑往返

本轮接入 Blender → 当前 Web Demo，沿用 D4 的任务、授权、资产版本、实例引用和独立试玩候选。基于本地 `1e90f54`（产品 D4 为 `514648b`）；保留工作区其他未提交修改。Unity、Xcode 未改造。

## 已实现

- 内容列表区分程序化配方、Blender 原生源和其他文件源，提供显式打开与保存同步入口。旧任务需原授权卡明确扩展 Blender 范围，不自动获得权限。
- Agent 默认无头，手工入口使用可见的专属 Blender。沿用认证 loopback、主线程执行、macOS sandbox-exec、目录外拒写探针及自有进程停止；未接入另一套 MCP、任意 Python 或素材服务。
- 类型化 begin 从当前资产版本创建候选；首次把门配方转换为模型，后续复制并重开已登记 `.blend`。edit 按稳定节点 ID 修改几何或基础颜色。源与 GLB 分别保存，发布版本不指向编辑器中的可变文件。
- 门框分成独立柱和过梁，门扇挂在偏置铰链下。导出保留稳定身份和语义；显式保存时为手工新增的未标记对象登记身份，遇到其他资产身份则拒绝，不静默丢弃自由几何。
- `source_kind=blender` 保留父源版本，不再携带可编辑 DoorRecipe；Web 链不要求 FBX。登记检查源版本，引用应用可指定实例子集，保留行为、实例 ID 和变换。引用冲突保留已登记源，源冲突保留不可变候选文件。
- 对象／组件与 ECS 模板使用实际 GLB 加载器、独立铰链旋转和按网格包围盒计算的碰撞。旧自定义代码未接入加载器时明确阻止物化，不自动覆盖普通行为源码。
- Blender Technical Artist 技能进入实际 Provider 请求，继续保留原制作、Debug、QA 技能。新授权使用不同内容与状态目录，不能重绑定旧会话。

## 操作

从作品的「选择实际内容」选择共享资产。原任务没有 Blender 权限时，准备并确认原有有限授权卡。点击「用 Blender 编辑」，编辑专属候选；点击「保存 Blender 源并同步导出」，再「更新 Demo」，显式打开新试玩。模型入口使用同一目标和工具。候选源被人工持有时，模型不能停止该窗口后覆盖它。

## Limitations

- 尚未完成“在专属 Blender 窗口手工改几何并保存”的 UI 验收。桌面自动化定位到原有的另一个 Blender 窗口，本轮没有操作或关闭它；Shell 显式保存回流已测，开发者模拟手工几何与真实模型编辑另行记录。
- 未完成所有要求的浏览器玩法断言、所有异常组合和重新授权后的完整编辑重演。不能把构建、画布出现或夹具碰撞断言称为全部玩法验收。
- 旧自定义消费者需要一次明确的加载器代码接入；不会自动把任意已有游戏代码转换为原生资产加载方式。当前生产能力以静态几何与基础材质为主。
- 碰撞使用每个网格的世界包围盒，不是三角网格物理；凹形门框需保持分段网格。没有动画、骨骼或任意模型生成承诺。
- 运行中的 Blender 操作不安全中断；排队取消可处理，状态未知时拒绝盲目写入重试。排队取消状态尚未跨进程持久化。
- 工作区全量 TypeScript 检查仍存在其他模块的错误；本轮新字段调用错误已修复。前端测试恢复了已有本地依赖链接。Corepack 在真实执行中下载 pnpm 11.13.0，Shell 测试的包管理器也准备了测试工程依赖；没有安装或升级 Blender、Unity、SDK 或第三方 MCP。
- 同一工作区存在其他并行开发差异，提交需仅包含本轮 Blender 差异。未推送、合并用户游戏分支或发布。

参考吸收了 [Blender MCP](https://github.com/ahujasid/blender-mcp) 的双向检查、对象与材质工作流；没有复制其任意 Python 接口或安装其服务。本轮技能为针对现有类型化工具编写的产品资源。
