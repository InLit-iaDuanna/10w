# SceneOps 项目初版与内容回流

## 用户路径

1. 用户在 Journey 填写核心体验、视角与风格、目标平台、技术架构和简化范围。
2. 确认方向只保存方向并创建游戏工程，不写入 Demo 内容，也不启动任务。
3. “发起初版制作”先准备 `project-demo` 授权卡，显示固定工具范围、整个任务的累计预算和登记工作区；用户发起后才写入内容并执行检查、构建和预览。
4. 工作台可修改门配方、单个场景实例的变换和 `KeyDoor` 行为参数。保存配方会创建新资产版本，并明确列出更新到该版本的引用实例。
5. “更新 Demo”复用原项目任务、工作区、授权期限和累计预算，重新物化当前内容并创建独立构建候选。最新请求构建成功后才切换试玩；失败时继续提供上一个成功候选。
6. 重开项目后，从 SQLite 记录恢复工作区、任务、场景、资产版本和候选引用。运行时拾取、开门等试玩状态不写回场景源。

详细策划、架构推荐和四张制作卡仍保留为高级路径；原卡片任务继续使用卡片分支与工作树。

## 权威源与派生物

| 内容 | 权威源 | 稳定身份与版本 | 运行使用方式 |
| --- | --- | --- | --- |
| 项目执行归属 | Project Intake 登记的项目 Demo 工作区 | `project_id` + `workspace_id` | 任务、授权、运行记录、候选和预览均校验该组合 |
| 程序化门 | Asset Library 的资产条目与 `DoorRecipe` 版本 | 共享 `asset_id`、不可变 `asset_version_id`、递增版本 | 宽、高、厚度和材质生成网格与碰撞尺寸 |
| 场景实例 | World Composer 场景版本 | 稳定实例 `id`、递增 `scene_version` | 位置、旋转、缩放逐实例读取；改单个实例不影响其他实例 |
| 门行为 | 场景实例上的 `KeyDoor@1` | 稳定 `behavior_instance_id` | 对象／组件读取行为实例；Miniplex 系统查询同一份组件数据 |
| 构建输入 | 选定场景版本及其引用的资产版本 | 候选记录保存源码、场景和资产版本引用 | 物化到工程内的 `.sceneops/demo-content.json` 与 `src/game/sceneops-demo-content.ts` |
| 试玩 | 最新成功且仍属最新请求的构建候选 | 工作区内单调候选序号 | 每次构建保留独立 `dist`；失败不替换当前可玩候选 |

`sceneops-demo-content.ts`、运行网格、碰撞几何和构建目录都是派生输入或产物，不能作为编辑源。物化内容只含项目内相对引用，不依赖其他工作区的绝对路径。

## 公共服务连接

- Asset Library 通过门配方定义和资产 recipe-version 接口公开参数类型、单位、默认值与范围。
- World Composer 通过 `KeyDoor` 定义、实例行为更新和共享资产版本换绑接口连接面板与任务执行。
- Agent Runtime 只调用上述服务与 Project Intake 的公开工作区物化服务；`project-demo` 使用固定 typed-tools 步骤，不调用自主制作模型。
- 构建候选记录关联项目、工作区、任务、源码信息、场景版本、资产版本和构建运行。

## Limitations

本批只提供确定性的钥匙开门夹具、程序化门配方和 `KeyDoor` 行为。它不接入付费素材、Blender 往返、通用行为编辑器、完整工作台改版或真实模型自主选工具制作，也不证明任意 idea 已能自动制作。
